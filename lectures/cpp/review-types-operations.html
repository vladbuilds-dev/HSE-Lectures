1.Типы данных

Тип данных — это свойство программной сущности, которое определяет три вещи:

  • множество допустимых значений;
  • допустимые операции;
  • низкоуровневое представление, то есть как интерпретировать биты.

Третий пункт — самый важный для лабы. Одна и та же последовательность битов означает разное в зависимости от типа: 11111111 11111111 11111111 11101111 — это либо −17, либо 4294967279. Разница только в том, как мы договорились читать старший бит.

Большинство типов в C++ прямо или косвенно строятся на фундаментальных:

  • Целые — int, short, long, long long
  • С плавающей точкой — float, double, long double
  • Символьные — char, char8_t, char16_t, char32_t, wchar_t
  • Логический — bool
  • Пустой — void
  • Нулевой указатель — std::nullptr_t (единственное значение nullptr, введён в C++11)

Составные типы: enum (под капотом целочисленный), struct (несколько переменных под одним именем), class (данные плюс методы, основа ООП).

Дополнительный код

Отрицательные числа хранятся в дополнительном коде. Рецепт: взять модуль числа, инвертировать все биты, прибавить единицу.

17  = 00000000 00000000 00000000 00010001
инверсия = 11111111 11111111 11111111 11101110
+1       = 11111111 11111111 11111111 11101111  = −17

Зачем так сделали — два ответа. Первый: ноль получается ровно один, тогда как в прямом коде есть +0 и −0. Второй, главный: сложи 17 и −17 обычным двоичным сложением — единицы побегут по цепочке, перенос за пределы 32 бит отбросится, останется ноль. Вычитание сводится к сложению, и процессору хватает одного сумматора вместо двух разных схем.

Проверь себя: почему ~x == -x - 1 для любого целого?

Из рецепта: -x получается как ~x + 1. Значит ~x = -x - 1. Например, ~42 == -43, ~0 == -1, ~(-1) == 0.

Что важно помнить

  • Доступны те же арифметические операции, что и для целых, кроме битовых и взятия остатка %.
  • Точность ограничена: большинство дробей невозможно точно представить в двоичной системе. Классика — 0.1 + 0.2 != 0.3.
  • Всегда знаковые — беззнакового float не существует.
  • Есть особые значения: +inf, -inf (деление ненулевого на ноль) и NaN (например, 0.0 / 0.0).
  • При смешивании типов менее широкий приводится к более широкому: float + double → double, int + float → float.
#include <iostream>
#include <cmath>    // для std::isnan, std::isinf

int main() {
    double infPos =  1.0 / 0.0;   // +inf
    double infNeg = -1.0 / 0.0;   // -inf
    double nanVal =  0.0 / 0.0;   // nan

    std::cout << infPos << ' ' << infNeg << ' ' << nanVal << '\n';

    if (std::isinf(infPos)) std::cout << "infPos is infinite\n";
    if (std::isnan(nanVal)) std::cout << "nanVal is NaN\n";
    return 0;
}
Прямо для Task 3

В лабе нужно объяснить, почему 10.25 + 7.1 при печати через setprecision(12) даёт не то, что ожидаешь. Ключ: 10.25 представимо точно (это 1010.01 в двоичной, конечная дробь), а 7.1 — нет (бесконечная периодическая дробь, обрезается по мантиссе). Ошибка появляется во втором слагаемом ещё до сложения.

Там же нужно показать нарушение ассоциативности: (a + b) + c != a + (b + c). Причина та же — каждое промежуточное сложение округляется, а порядок округлений разный.

Проверь себя: почему сравнение a == b для double опасно?

Потому что два разных пути вычисления одного и того же математического значения дают разные битовые представления. Правильный способ — сравнивать модуль разности с малым порогом: std::abs(a - b) < eps. Порог подбирается под масштаб чисел, а не берётся «на глаз».

4.Логический тип bool

Принимает ровно два значения — true и false. Занимает обычно 1 байт (не 1 бит: минимальная адресуемая единица памяти — байт).

int a = 5, b = 10;

bool isGreater = a > b;    // false → печатается как 0
bool isEqual   = (a == b); // false → печатается как 0

Операции сравнения: > < >= <= == !=. Логические: && (и), || (или), ! (не).

Короткое замыкание

Это свойство && и ||, которое нужно понимать, а не просто знать:

  • Левый операнд гарантированно вычисляется раньше правого.
  • Если слева у || получилось true — правая часть не вычисляется вообще.
  • Если слева у && получилось false — правая часть тоже не вычисляется.
// Классическая защита от деления на ноль:
if (n != 0 && total / n > 10) { ... }
// если n == 0, деление просто не выполнится

5.Операция sizeof Task 5

Унарная операция, возвращает размер типа или объекта в байтах.

sizeof(char) == 1;   // всегда 1 по стандарту
sizeof(int)  == 4;   // обычно 4, но зависит от платформы
Главное свойство: sizeof ничего не выполняет

Он анализирует только тип выражения, а само выражение не вычисляется. Побочных эффектов не будет.

long long x;

sizeof('a');    // 1 — в C++ символьный литерал имеет тип char
sizeof(1 / 0);  // 4 — тип int; деления на ноль НЕ произойдёт
sizeof(x = 1);  // 8 — размер long long; x не изменится
sizeof(++x);    // 8 — x не увеличится

6.Инкремент и декремент

Унарные операции, изменяющие значение на единицу. Применимы только к lvalue — то, что имеет имя и адрес, то есть к переменной.

int x = 0;
x++;   // постфиксный инкремент → x == 1
++x;   // префиксный инкремент  → x == 2
x--;   // постфиксный декремент → x == 1
--x;   // префиксный декремент  → x == 0

К prvalue — литералу или временному значению — применить нельзя:

++5;        // ошибка: 5 — prvalue
(x + 1)--;  // ошибка: (x + 1) — prvalue

// error: lvalue required as increment operand

В чём разница префикса и постфикса

ФормаЧто возвращаетКатегория
++xновое значение, сам аргумент после измененияlvalue
x++старое значение, копию до измененияrvalue
 
int x = 0;
std::cout << ++x << '\n';  // печатает 1, x == 1
std::cout << x++ << '\n';  // печатает 1, x == 2

--x = 10;  // допустимо: --x вернул lvalue
x-- = 11;  // ошибка компиляции: x-- вернул rvalue

Практическое следствие: постфиксная форма обязана сохранить копию старого значения перед изменением. Для встроенных типов компилятор это оптимизирует, но для тяжёлых пользовательских типов в цикле ++it дешевле, чем it++. Отсюда привычка писать ++i в заголовке for.

7.Битовые операции Task 1, 4

ОперацияНазваниеПравило

Разбор на числах из конспекта

x = 5  = 00000101   (биты 0 и 2)
y = 3  = 00000011   (биты 0 и 1) 

x & y  == 1   // 00000001 — общий только бит 0
x | y  == 7   // 00000111 — объединение битов 0, 1, 2
x ^ y  == 6   // 00000110 — бит 0 есть у обоих, вычёркивается
~x     == -6  // ...11111010 — правило ~x = -x - 1

Сдвиги

5  << 2  == 20   // 00000101 → 00010100, умножение на 4
16 >> 2  == 4    // 00010000 → 00000100, деление на 4
Здесь конспект противоречит сам себе

В сводке написано, что при сдвиге вправо «освободившиеся биты заполняются нулями», а абзацем ниже — что для знаковых копируется старший бит. Верно второе.

Для знаковых типов сдвиг вправо арифметический: слева размножается знаковый бит, поэтому отрицательное остаётся отрицательным. Для беззнаковых — логический: слева нули.

Побочный эффект: округление идёт вниз, а не к нулю. -17 >> 2 даёт -5, тогда как -17 / 4 даёт -4. Сдвиг не эквивалентен делению для отрицательных чисел — это отдельный вопрос в Task 1.

Полезная деталь для README: до C++20 поведение правого сдвига отрицательных было implementation-defined, стандарт его не гарантировал. C++20 закрепил арифметический сдвиг. Курс идёт на C++23, значит у вас гарантировано.

Проверь себя: чему равно 42 & -17 и почему?

42. Смотри на биты: -17 в дополнительном коде — это все единицы, кроме бита 4. А у 42 (это 32+8+2, биты 5, 3 и 1) бит 4 и так нулевой. Значит И ничего не обнуляет, и результат равен 42.

По той же причине 42 | -17 == -17: у -17 уже всё заполнено единицами, кроме бита 4, а 42 туда единицу не приносит.

Для Task 4

Замерять придётся три пары: x / 2 против x >> 1, x * 2 против x << 1, x % 2 == 0 против (x & 1) == 0. Заранее держи в голове гипотезу: современный компилятор сам заменяет деление на константу-степень двойки сдвигом, поэтому разницы может почти не быть — и объяснить отсутствие разницы будет ценнее, чем показать её. Именно для этого в задании требуют volatile: он запрещает оптимизатору выбрасывать вычисления.

8.Операция static_cast Task 2

Явное преобразование типа. Синтаксис: static_cast<целевой_тип>(выражение).

int x = 2;
int y = 2000000000;

std::cout << x / y << '\n';
// 0 — целочисленное деление отбрасывает дробную часть

std::cout << static_cast<double>(x) / y << '\n';
// 1e-09 — x стал double, деление стало вещественным

std::cout << x * y << '\n';
// переполнение знакового int — это UB, неопределённое поведение

std::cout << static_cast<int64_t>(x) * y << '\n';
// 4000000000 — умножение идёт уже в 64 битах
Ключевое различие для Task 2

Переполнение беззнаковых типов определено стандартом: арифметика идёт по модулю 2n, то есть UINT32_MAX + 2 честно даёт 1. Это законно и предсказуемо.

Переполнение знаковых — это undefined behavior. Компилятор вправе предполагать, что его не бывает, и выкидывать проверки. Формально INT32_MAX + 2 не «даёт INT32_MIN + 1» — программа просто перестаёт иметь смысл, хотя на практике обычно печатает именно это.

Вот это различие — законное заворачивание против UB — и есть ответ на третий и четвёртый вопросы Task 2.

9.Операция «запятая»

Объединяет несколько выражений в одно. Вычисляет их слева направо, а возвращает результат последнего.

int x = 1, y = 2;

int z = (++x, y--, x + y);
// ++x   → x = 2
// y--   → вернул 2, затем y = 1
// x + y → 2 + 1 = 3, это и попадает в z

std::cout << z;  // 3

Не путай с запятой-разделителем в объявлении int a = 1, b = 2; или в списке аргументов функции — там это не операция.

10.Что в исходном конспекте напутано

Файл stepik.txt копировался со страницы курса, и часть содержимого пострадала. Не заучивай оттуда следующее:

  1. Пропали все угловые скобки. В тексте стоит #include без ничего и static_cast(expression) без типа. Правильно — #include <iostream> и static_cast<double>(x). Браузер съел то, что принял за HTML-теги.
  2. Противоречие про сдвиг вправо — в сводке нули, в подробном разборе знаковый бит. Верен знаковый бит для знаковых типов.
  3. Путаная нумерация битов. В разборе x | y написано, что у пятёрки единицы во «втором и четвёртом» битах. У 5 = 00000101 единицы в битах 0 и 2, если считать с нуля справа. Нумеруй с нуля и от младшего — так принято везде.
  4. Диапазоны вещественных напечатаны как «10-38» и «1038» — это потерянные степени, читай как 10−38 и 1038.
  5. Про long: «обычно 8 байт» — только на Linux и macOS, на Windows 4. Не полагайся, используй <cstdint>.
  6. Про and, or, not: «унаследованы из C» — не совсем. Это альтернативные токены самого C++; в C они появляются только через заголовок <iso646.h>. Что до «плохого стиля» — это вопрос принятого соглашения, а не правило языка, но в вашем курсе пиши &&, ||, !.
  7. using namespace std; — в примерах Степика он есть, но в реальном коде и в лабе так не делают: это тянет в область видимости сотни имён и приводит к конфликтам. Пиши std::cout явно.
